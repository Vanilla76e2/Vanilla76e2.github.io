# FAQ

## Что означает иерархия «Вид → Тип → Вариант → Компонент»?

Это четыре уровня справочника [Компоненты](./Справочники/Компоненты.md), от общего к частному:

| Уровень       | Что это                                          | Пример                                             | Зачем нужен                                                                                                                                                                    |
| ------------- | ------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Вид**       | Широкая категория оборудования                   | *Двигатели*, *OnTrak*, *Units*                     | Группирует типы для удобной навигации. Не влияет на логику работы программы, наименования могут быть произвольными.                                                            |
| **Тип**       | Обобщение для группы взаимозаменяемых деталей    | *Unit Base*, *Unit Extended*                       | Определяет, какие детали могут встать в один и тот же слот [шаблона](./Справочники/Шаблоны.md). Здесь включают флаг **Головной инструмент?** и задают пороги матрицы вибраций. |
| **Вариант**   | Конкретная спецификация типа с партийным номером | *151298 — Unit Base 0.5*, *151299 — Unit Base 0.6* | Определяет технические характеристики и парт-номер. Детали разных вариантов одного типа взаимозаменяемы в сборке без смены шаблона.                                            |
| **Компонент** | Физический экземпляр с серийным номером          | *S/N 2024-0047*                                    | Единица учёта: именно компонент ставят в [сборку](./Справочники/Сборки.md), отправляют в поле, обслуживают.                                                                    |

**Ключевая идея**: тип задаёт взаимозаменяемость — если слот в шаблоне ожидает тип *Лопасть*, туда встанет любой компонент этого типа, будь он варианта *Unit Base 0.5* или *Unit Base 0.6*. Это позволяет менять детали с разными спецификациями без перестройки шаблона.

## Можно ли отправить неукомплектованную сборку?

Да. Программа покажет предупреждение, но позволит подтвердить отправку. То же самое при завершении [заказ-наряда](./Рабочий%20цикл/Заказ-наряд.md) — если сборка не полностью укомплектована, появится диалог **Завершить всё равно**.

Индикатор **Укомплектованность** (N/M) на вкладке [Сборки](./Справочники/Сборки.md) и на [Главной](./Рабочий%20цикл/Главная.md) всегда показывает текущее состояние слотов.

## Что за баннер «Принять обновление / Оставить мои изменения»?

Это **конфликт редактирования**, а не обновление самой программы. Он появляется, когда вы редактируете документ ([заказ-наряд](./Рабочий%20цикл/Заказ-наряд.md), [рейс](./Рабочий%20цикл/Рейсы.md) и др.), а в это время другой пользователь сохранил изменения в тот же документ.

- **Принять обновление** — ваши несохранённые правки будут заменены версией с сервера.
- **Оставить мои изменения** — вы продолжите работать со своей версией и при сохранении перезапишете серверную.

> Совет: если вы не уверены, чьи правки важнее — примите обновление, просмотрите актуальную версию и внесите свои изменения заново.

## Где смотреть историю оборудования?

В двух местах:

- **[Рейсы](./Рабочий%20цикл/Рейсы.md)** — журнал спусков: даты, часы, метры, инцидент. Отсюда же открывают отправку и полевые данные рейса.
- **[Обслуживание](./Рабочий%20цикл/Обслуживание.md)** — записи обслуживания сборки: окно полевых данных отправки, заказ-наряды, статусы.
- **[Сводка](./Отчёты/Сводка.md)** — хронология одной сборки по серийному номеру: отправки, рейсы, обслуживания, операции. Открывается из контекстного меню сборки или из полевых данных.

Если нужна статистика по всему парку за период (а не по одной единице) — используйте [Аналитику](./Отчёты/Аналитика.md).

## Как быстро укомплектовать новую сборку?

Создайте пустую сборку по шаблону и нажмите **Мастер создания**. Укажите дату, исполнителя, для слотов — вариант и серийный номер. Мастер заведёт компоненты, поставит их в дерево и закроет связанные обслуживание и заказ-наряд. Если детали уже есть в справочнике, ставьте их операцией **Сборка** в заказ-наряде, не кнопкой **Назначить компонент** на вкладке сборок. Подробнее: [Сборки](./Справочники/Сборки.md) и [Как завести сборку](./Сценарии/Как%20завести%20сборку.md).

## Можно ли завести заказ-наряд на деталь, а не на всю сборку?

Да. Запись [обслуживания](./Рабочий%20цикл/Обслуживание.md) и [заказ-наряд](./Рабочий%20цикл/Заказ-наряд.md) заводят на отдельный [компонент](./Справочники/Компоненты.md). Полевые данные для такой записи не обязательны. Если у типа компонента есть шаблон, а сборки ещё нет, программа создаст её. Первая операция **Сборка** / **Разборка** может подставить сборку к наряду, у которого её ещё не было.

## Где смотреть наработку в часах?

- Карточка [компонента](./Справочники/Компоненты.md) — таблица **Время наработки**; из строки ПД открывается исходный документ.
- Шапка [сводки](./Отчёты/Сводка.md) и периоды на шкале.
- Шапка [заказ-наряда](./Рабочий%20цикл/Заказ-наряд.md).
- Строка [полевых данных](./Рабочий%20цикл/Обслуживание.md) в таблице обслуживания.

Часы берутся из циркуляционного времени в [рейсах](./Рабочий%20цикл/Рейсы.md) (с сотыми), плюс вручную добавленные строки в карточке компонента. Полевые данные эти часы только суммируют по отправке.

## Почему не пускает на сервер после обновления?

Desktop и API должны совпадать по контракту. Сообщение на экране входа скажет, кого обновлять: сервер или приложение. Ставить нужно **ту же** версию, что у второй стороны. См. [авторизацию](./Начало%20работы/Авторизация.md) и [установку](./Начало%20работы/Установка%20и%20обновление.md).

## Где спрятаны ПКМ, Ctrl+W и горячие клавиши?

В главе [Продвинутое использование](./Продвинутое%20использование.md): контекстное меню (в том числе **Создать операцию** из дерева наряда), жёлтое предупреждение в описании, таблица клавиш.
